# v0.13.0 - Kimi Code 与当前 Agent CLI 适配

MCO 新增 Kimi Code CLI 支持，并更新 Antigravity、Pi、OpenCode、Hermes、Codex 和 Grok 的 CLI 适配。

## 主要变化

- 新增 Kimi Code 2.5.2 支持，包含随包分发的只读/写入工具配置、模型选择、JSONL 回答解析，以及通过文件传递回答的 chain、debate 和 synthesis 阶段。
- 更新 OpenCode 2 的命令参数与模型选择、Hermes 的上下文控制，以及 Antigravity/Grok 的权限模式。
- 修复 Pi/Hermes 的模型服务商配置在 CLI、MCP 和多阶段执行中丢失的问题。
- 修复 Pi 错误与截断、Codex 非零退出、Grok 无交互权限拒绝被误判为成功的问题；JSONL 回答保留 Unicode 行分隔符和段落分隔符。

## 兼容性说明

- OpenCode 2 不再支持原有插件隔离机制；相关请求在 strict 模式报错，在 best-effort 模式丢弃。
- Pi 指定 provider 时必须同时指定 model。Hermes 通过 `--ignore-rules` 禁用上下文文件，这也会禁用记忆和预加载技能。
- 只读 debate 和 synthesis 会拒绝无法提供只读模式的 Provider。Hermes 必须显式选择 `yolo`。
- Kimi 工具配置不构成操作系统沙箱，也不会禁用已安装的 hooks。`--transport acp` 对 Kimi 使用 shim 回退。
- Grok 出现无交互权限拒绝诊断时会被标记为失败，即使后续工具恢复执行也是如此。

## 验证结果

Antigravity、Pi、Kimi、Codex、Grok 均完成真实文件读写；Codex→Kimi chain 和 Kimi debate/synthesis 也已通过。OpenCode 推理受认证或免费额度限制，Hermes 受其配置的本地模型端点不可用阻塞。未真实调用 Claude Code。

自动化测试通过 526 项 Python 测试和 19 项 Node 测试，另有 3 项平台测试跳过；包构建与安装检查通过。审计的 CLI 版本及验证边界见[兼容性记录](https://github.com/mco-org/mco/blob/v0.13.0/docs/reference/agent-compatibility-2026-11-07.md)。

## 安装或升级

```bash
npm install -g @tt-a1i/mco@0.13.0
mco --version
```

PATH 中需要 Python 3.10 或更高版本。MCO 仅通过 npm 发布。
